PASO 1.1El traductor hacia el depósito nuevo

🔧 Técnico

nuevo · lib/file-reception/transport/r2.ts

  • Archivo nuevo que habla con R2 usando aws4fetch (~7 KB; se descarta el SDK de AWS por ser muy pesado para el “bundle”).
  • presignPut(key, size): emite el vale de subida. F1 firma el Content-Length → R2 rechaza en la puerta cualquier archivo más grande que el declarado (el límite de 50 MB se aplica en el depósito, no solo en la base de datos).
  • presignGet(...): vale de bajada. F5 fuerza la descarga como archivo “neutro” para que un .svg malicioso no se ejecute al previsualizar.
  • deletePrefix(...): borra toda la carpeta de una (R2 lista recursivo).
PASO 1.1El traductor hacia el depósito nuevo

💬 En criollo

Escribimos el “manual de instrucciones” para hablar con el depósito nuevo.

  • Define cómo se emiten los vales para subir, para bajar y cómo se borra.
  • El vale de subida ahora dice “máximo tantos kilos”: si el archivo pesa de más, el depósito lo rechaza en la entrada.
  • El vale de bajada obliga a que el archivo se descargue, nunca se “abra solo” en pantalla (más seguro).
PASO 1.2Ventanilla del empleado

🔧 Técnico

nuevo · app/api/reception/staff/presign/route.ts

  • Endpoint nuevo protegido por getClaims(): solo responde a un empleado con sesión iniciada.
  • Solo dos operaciones: get (bajar) y delete (borrar). put queda excluido: el mostrador nunca sube archivos.
  • F4 el cliente no manda la ruta a borrar como texto libre. Manda sessionId + fileId (validados como UUID) y el servidor arma la dirección ${'{'}sessionId{'}'}/${'{'}fileId{'}'}/. Así nadie puede pedir “borrá todo”.
  • Límite de uso (rate-limit) por empleado.
PASO 1.2Ventanilla del empleado

💬 En criollo

Una ventanilla nueva, solo para empleados logueados, que reparte vales para descargar o borrar.

  • El empleado no dice “borrá esta carpeta” con texto libre. Solo da el número de la visita y el número del archivo.
  • El sistema arma la dirección exacta por su cuenta → es imposible pedir que borre de más.
  • Tiene un tope de pedidos por persona, para que nadie abuse.
PASO 1.3Reconectar el mostrador

🔧 Técnico

modificar · lib/file-reception/transport/storage.ts

  • Hoy createStorageBackend() firma vales en el navegador usando el cliente de Supabase. Eso se elimina.
  • Ahora pide los vales a la ventanilla del paso 1.2: signedUrl → {op:'get'}, removePrefix → {op:'delete'}.
  • uploadFile queda como “stub” (función vacía): la interfaz lo exige pero el mostrador nunca sube.
  • La interfaz StorageBackend no cambia → el resto del mostrador no se toca.
PASO 1.3Reconectar el mostrador

💬 En criollo

La pantalla del mostrador deja de “firmar vales por su cuenta” y pasa a pedírselos a la ventanilla nueva.

  • ¿Por qué? Firmar vales del depósito nuevo necesita una clave secreta, y eso no puede vivir en un navegador.
  • Para el empleado es idéntico: cambia quién firma detrás de escena, no lo que ve.
PASO 1.4Reapuntar la subida del cliente

🔧 Técnico

modificar · app/api/reception/sessions/[sessionId]/upload-url/route.ts

  • Es la ventanilla que ya atendía al kiosko (con su control de aprobación y sus topes de 30 archivos / 200 MB).
  • Se reemplaza una sola línea: el vale de Supabase (createSignedUploadUrl) por presignPut(path, size) hacia R2.
  • La respuesta y todos los controles quedan iguales.
PASO 1.4Reapuntar la subida del cliente

💬 En criollo

La ventanilla que ya atendía al cliente ahora le entrega el vale del depósito nuevo en vez del viejo.

  • El cliente sube exactamente igual: no nota absolutamente nada.
  • Las mismas reglas de antes (cuántos archivos, cuánto peso, que esté aprobado) siguen vigentes.
PASO 1.5Simplificar el borrado

🔧 Técnico

modificar · app/api/reception/sessions/[sessionId]/files/[fileId]/route.ts

  • Supabase obligaba a recorrer dos niveles de “carpetas” para juntar las rutas y borrarlas.
  • Se reemplaza por deletePrefix de R2: un solo prefijo y listo (R2 lista recursivo).
  • Menos código, mismo resultado.
PASO 1.5Simplificar el borrado

💬 En criollo

Antes, borrar un archivo era abrir carpeta por carpeta. El depósito nuevo borra toda la carpeta de una.

  • Mismo resultado para el empleado, con menos pasos por dentro.
PASO 1.6Cerrar las puertas (CORS)

🔧 Técnico · 3 ajustes

  • Bucket R2: permitir subir/bajar solo desde los orígenes del kiosko y el mostrador. Acceso público = OFF.
  • F2 cors.ts fail-closed: si la lista de orígenes permitidos queda vacía, denegar (hoy deja pasar a cualquiera).
  • F3 en proxy.ts, las rutas /staff/** aceptan solo el origen del mostrador (evita que una web ajena dispare pedidos con la sesión del empleado — riesgo tipo CSRF).

CORS = la regla que decide qué páginas tienen permiso de hablarle a nuestro sistema.

PASO 1.6Cerrar las puertas (CORS)

💬 En criollo

Le decimos al depósito y al sistema: “solo aceptá pedidos que vengan de nuestras propias pantallas, de nadie más”.

  • El depósito no es público: a los archivos solo se llega con un vale válido.
  • Si por error la lista de “pantallas permitidas” quedara vacía, ahora el sistema dice que no (antes dejaba pasar a cualquiera).
  • Las ventanillas de empleados solo le hablan a la pantalla del mostrador.
PASO 1.7Llaves e instalación

🔧 Técnico

  • Cargar en Vercel (el servidor) las variables: R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_BUCKET, R2_ENDPOINT.
  • El kiosko no recibe ninguna variable nueva: R2 queda detrás de la ventanilla (broker).
  • Instalar la herramienta de firma: pnpm add aws4fetch.
PASO 1.7Llaves e instalación

💬 En criollo

Guardar las llaves y la dirección del depósito nuevo en un lugar cerrado del servidor, e instalar la herramienta que firma los vales.

  • El cliente nunca ve ninguna de esas llaves: viven solo del lado seguro.
VERIFICACIÓNAntes de dar la fase por buena

🔧 Técnico · circuito de prueba

  • Tocar timbre → aprobar → subir 2–3 archivos desde el kiosko.
  • Confirmar PUT 200 a R2 y que los objetos aparezcan en <sessionId>/<fileId>/<nombre> (dashboard o wrangler r2 object get).
  • “Descargar todo” (todavía del lado del navegador) baja el ZIP OK.
  • markDone vacía la carpeta de la sesión; removeFile borra la del archivo.
VERIFICACIÓNAntes de dar la fase por buena

💬 En criollo

Probamos el circuito completo con archivos de prueba.

  • Timbre → aprobar → subir → chequear que aparecen en el depósito nuevo → descargar.
  • Verificar que borrar deja todo limpio.
  • Recién con eso damos la Fase 1 por terminada.
Para tener a mano

Glosario técnico

URL prefirmada / “vale”Permiso temporal para subir o bajar un archivo puntual, válido pocos minutos.
key / prefijoLa “dirección” de un archivo dentro del depósito: visita/archivo/nombre. Un prefijo es el comienzo de esa dirección (una carpeta).
UUIDUn código largo y único (ej. 3f2a…-9c) que identifica una visita o un archivo sin ambigüedad.
CORSLa regla que decide qué páginas web tienen permiso de hablarle a nuestro sistema.
fail-closed“Ante la duda, negar”. Si falta una configuración de seguridad, el sistema cierra en vez de abrir.
rate-limitTope de pedidos por persona/tiempo, para evitar abusos.
stubUna función que existe por requisito pero no hace nada (porque acá no se usa).
bundleEl “paquete” de código que viaja al navegador. Cuanto más liviano, más rápido carga.
Content-LengthEl tamaño declarado de un archivo. Firmarlo deja que el depósito rechace lo que no coincida.
