Plata — la escalera de cantidad

El cluster más caro y el más alineado con el confident-wrong que el proyecto persigue. Tres hallazgos, un mismo origen: el piso o el $0 de una escalera se presenta como precio plano.

AltaCM-1Calcular Montos

El “desde” prometido nunca se escribe en el texto

Escalera continua ($480 / $300 / $150) sin cantidad → monto = Math.min(values) y el texto sale “$150 por hoja”, plano. El campo desde viaja aparte y ni el prompt ni el texto lo nombran; el compositor copia texto verbatim.

↓ sub-cotiza 3,2× — el tramo 51-250 u presentado como el precio de 5 u
Fixescribir "desde $piso (según cantidad)" dentro de texto.
AltaCM-2Calcular Montos

Cantidad fuera de la escalera: cotiza el tramo 1 y lo totaliza

cantidad=25 con tramos 1-3 / 4-10 / 11-20 → ningún find matchea → monto queda en precio_lista (tramo 1) y, como es >0, el fallback de escalón inferior no corre → con multiplica sale “TOTAL $200.000 por 25 unidades”.

↑ sobre-cotiza 1,23× con formato autoritativo (a ≥11 pagan menos)
Fixcaer al último tramo aplicable, no al tramo 1.
AltaAC-1Armar Candidatos

precio_lista = 0 con escalera se muestra como precio: $0

Río arriba del anterior: fmt(0) devuelve '$0' (solo filtra n==null) y no se emite ninguna línea de rangos. El Agente Relevancia ve “$0” y puede descartar el candidato correcto — que entonces Calcular Montos nunca llega a ver.

el candidato correcto (rifas) puede desaparecer antes del cálculo
Fixcon rangos > 0, mostrar "desde $piso" en vez de $0.
02

Logs silenciosos — telemetría perdida

Fallas que no dejan rastro: onError:continueRegularOutput, exception when others then null, y una unidad de tiempo equivocada. El log es lo que usás para saber si el bot funciona; cuando miente, es peor que el error que oculta.

AltaH1Log Turno · enum

envio_fallido no existe en el enum bot.accion

Cuando Chatwoot no entrega, Chequear Envio pone accion:'envio_fallido' y Log Turno lo inserta en una columna enum NOT NULL. El valor no está en el enum → el INSERT rebota mudo → no se escribe la fila justo en el turno que falló la entrega, que es el caso exacto que ese nodo se construyó para registrar. Los tests dan verde falso.

telemetría de fallo de envío = 0 justo cuando importa
Fixalter type bot.accion add value 'envio_fallido';
AltaH2Strike Tier-2 · enum

firewall_tier2_topicalAlignment no existe en el enum

El guard se llama topicalAlignment; fw_log arma 'firewall_tier2_'||reason y el enum tiene offtopic, no topicalAlignment. fw_log traga el error con exception when others → un refusal topical de Tier-2 por debajo de strike-max no loguea. (jailbreak sí cuadra.)

Fixmapear topicalAlignment → offtopic en Router Fail Tier-2 (cierra la cardinalidad abierta §h).
AltaDE-A1Decidir

El cap de 25 respuestas/24 h es código muerto (ms vs segundos)

Date.now() está en milisegundos; Chatwoot manda created_at en segundos. La resta nunca es < 86.400.000 → botOut24 siempre vacío → las ramas cap no se alcanzan jamás. El bot no tiene tope real de respuestas, en prod (v10-live y v9). Agravante: Get Historial no pagina.

sin freno de volumen — riesgo de costo y de baneo de Meta
Fixconvertir a segundos + paginar Get Historial — o decidir que no hay cap.
03

Degradan en silencio — medios

Med · AC-2jsonb como string degrada todo. Armar Candidatos asume jsonb parseado. Si el nodo Postgres lo devuelve string (según versión/config), atributos→ todo a “se confirma por mail” y rangos_cantidad→null reintroduce el confident-wrong 1,7× en un por_pagina. Falta guard de parseo.
Med · AC-3Error SQL indistinguible de búsqueda vacía. El item de error de Buscar Candidatos lo come el filter(r&&r.producto_id) → motivoVacio='busqueda_vacia' miente si la base falló. Clase B-18.
Med · CM-3Crash con elegidos:[null]. TypeError mata el turno entero sin log (familia B-13). Un guard lo cierra.
Med · CM-4Cantidad sin normalizar. "1.000" (formato es-AR) → Number()=1 → cotiza el tramo 1 a quien pidió mil.
Med · DE-A2Falsos positivos de injection con vocabulario de imprenta. “nuevo rollo de vinilo”, “ME DAN 100 tarjetas”, “el control de calidad” disparan el mensaje anti-injection en vez de la cotización. Faltan \b.
Med · DE-M1Historial truncado. avisoDado y el cap se calculan sobre la última página (~20 msgs) → el bot repite el mail en conversaciones largas.
Med · EP-1El cap de 12 tokens pierde señal del cliente. En la rama opciones, 4 nombres largos del LLM llenan los 12 lugares → los tokens nuevos del cliente (kraft, anilladas) quedan afuera.

Bajos y latentes

Bajo · H5Asimetría ü/ç. El JS folda ü→u, el translate del SQL no. Real en mecanismo, latente: cero ü/ç en el catálogo hoy. Se activa con una curación futura (“bilingües”) o un acento NFD.
Bajo · H4Ruteo strike-max (§2i). firewall_check devuelve silence para rate y strike-max; el Switch rutea solo por action → el atacante recibe “frená, mucho volumen”. Ya backlogueado.
Bajo · H6final no se anula en envío fallido. La entrega solo vive en accion/senales; un select final ingenuo muestra texto no entregado.
Bajo · CM-5Precios con decimales rompen el guard del verificador. fmt(88.5)→ el regex del verificador corta en la coma → falsa ALERTA y tumba el mensaje correcto. Solo si el catálogo deja de ser entero.
Bajo · AC-4“también hay packs de ” colgante + es_default/orden/ejes_variantes descartados del candidato (el default sobrevive solo como posición 1).
Bajo · EP-2Gramaje no se conserva como dice el comentario (“80 gr” se pierde; “80gr” no matchea “75 gr” separado); whitelist a[0-5] excluye a6.
